Como eu fiz a Pijamoon

De uma loja estática no bootcamp a um commerce serverless na AWS, orientado a eventos, com toda a infraestrutura em código (AWS CDK).

A arquitetura hoje

  • Site: CloudFront na frente de um S3 privado. Enquanto o CloudFront esteve bloqueado na conta, o site rodou no Amplify; quando liberaram, voltei para o CloudFront, que tem 1 TB por mês de tráfego grátis.
  • API: API Gateway com limite de requisições. O checkout e os pedidos exigem login (Amazon Cognito, token JWT).
  • Catálogo (síncrono): Lambda + DynamoDB, com cache de 60 s na memória da Lambda.
  • Checkout (assíncrono): responde na hora com 202 Accepted e publica um evento. EventBridge → fila SQS (com DLQ) → Lambda grava o pedido, uma vez só.
  • Custo: teto de US$ 20 por mês, com alerta no AWS Budgets e um disjuntor que tira o site do ar se o tráfego disparar.
  • Entrega: tudo em AWS CDK (4 stacks), testado a cada pull request e implantado a cada merge pelo GitHub Actions, sem nenhuma chave da AWS guardada no GitHub (OIDC).

E se a Pijamoon ganhasse um app mobile?

Hoje a API já é o back-end compartilhado: um app mobile usaria as mesmas rotas, o mesmo login do Cognito e o mesmo fluxo de pedidos, sem duplicar regra de negócio. Um BFF (Backend for Frontend) só entraria se o app precisasse de respostas num formato muito diferente do site, por exemplo, juntando várias chamadas numa só para economizar dados no celular.
